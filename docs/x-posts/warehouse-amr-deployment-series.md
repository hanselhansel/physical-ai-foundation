# X Post Series: Warehouse AMR Deployment

Status: Parked, not publication-ready.

A 12-post draft series for X. Every quantitative claim requires a permanent source link, source date, fact-check date, and approved wording before publication. Restart only after a validated portfolio case is approved for external communication.

## Post 1: Why deployments fail

Most warehouse robot projects fail before the robot moves. The WMS integration and SKU master data break first. The robot gets the blame. The real project is the plumbing.

## Post 2: The walking precondition

If your pickers do not spend 60-70% of their shift walking, a warehouse robot will not save you money. Fix the layout, batching, or wave timing first. Walk time is the precondition.

## Post 3: The five categories

5 warehouse automation categories, 1 decision tree. Large RDC case handling = Symbotic. Dense e-commerce storage = AutoStore/Exotec. Fast piece-picking = Locus/6 River. Match the category to your workflow, not the robot to the hype.

## Post 4: Walmart is not buying robots

Walmart's Symbotic deal is not a robot purchase. It is a 15-year infrastructure and service partnership across 42+ RDCs with a $22.5B backlog. The lesson: warehouse automation at scale is a utility contract, not a hardware order.

## Post 5: SKU data is the invisible prerequisite

Bad SKU data kills robot deployments. Dimensions, weights, barcodes, and images must be right. One wrong dimension breaks palletization, pick instructions, and throughput. Data governance is the invisible prerequisite.

## Post 6: The parallel fallback

Never run a robot pilot without a parallel manual fallback. You need a baseline to prove ROI. You also need a safety net when the integration fails. The fallback is not waste. It is insurance.

## Post 7: The metric that matters

Stop measuring robot speed. Start measuring labor cost per pick. A fast robot that waits for tasks is expensive. A slow robot that cuts walking and errors is profitable.

## Post 8: How to evaluate a vendor

Vendor demos are optimized to impress you. Run a structured evaluation instead: deployment speed, capital model, WMS integration, uptime SLA, scalability, human factors, exit terms. Score each before you see the robot move.

## Post 9: The 12-week rollout

A 12-week AMR rollout for a 50,000 sq ft 3PL warehouse: week 1 design, weeks 2-4 pilot, weeks 5-10 expand, weeks 11-12 lock SOPs and document ROI. Parallel manual picking runs the whole time.

## Post 10: Mid-market 3PLs should start here

For mid-market 3PLs, collaborative AMRs beat full-stack automation. Lower capital, faster deployment, reversible if it fails. You trade the headline of 'lights out' for the reality of 'cash positive in months'.

## Post 11: Safety is not an add-on

Safety is not an add-on. Before the first robot runs: E-stops, light curtains, speed limits, signage, training, incident reporting, and insurance. Skip the checklist and the first incident will define the project.

## Post 12: When to roll back

Roll back a robot pilot if: throughput gain is below 10%, error rate rises, uptime stays below 95%, or a safety incident traces to design. A failed pilot is a good outcome if you learn cheaply. A failed rollout is expensive.
