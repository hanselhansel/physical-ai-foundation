# Physical AI Portfolio Roadmap

Updated: 2026-08-31

## Work-in-progress limits

- One active build lane.
- One active validation lane.
- External waiting items do not consume either lane.

## 1. Portfolio reorganization

Outcome: The approved Portfolio, Projects, Contributions, Outreach, and Forks repository-purpose structure is live.

Gate: All content lands, each migration reaches `VERIFIED`, local/cached/live `main` match, links pass, and the upstream contribution remains accessible.

## 2. Flagship experiment charter

Outcome: One experiment is selected based on the decision it informs, evidence it produces, reproducibility, portfolio relevance, effort, and stop condition.

Candidates include Open-RMF, a WMS-to-fleet integration contract, a brownfield deployment case, and a substantive upstream contribution.

Gate: The charter names the target decision, success criteria, falsification condition, required evidence, and downstream artifact.

## 3. Experiment design

Outcome: The selected experiment has a separate approved design and plan.

If Open-RMF is selected, cover image compatibility, ARM64 execution, current RMF web architecture, runbook corrections, observations, and warehouse interpretation.

Gate: Design approved, environment preflight green, and evidence template instantiated.

## 4. Runtime validation

Outcome: Execute with exact versions, commands, logs, screenshots, failures, observations, and a continue, revise, park, or drop decision.

Gate: An independent rerun or review confirms the evidence is reproducible enough for its intended claim.

## 5. Warehouse artifact integration

Outcome: Findings update a named warehouse project artifact and link back to evidence.

## 6. Portfolio retrospective

Outcome: Record what to repeat, change, stop, and test next.

## 7. Outreach activation

Outcome: One validated case is approved for external communication.

Gate: Claims are source-checked, private records remain outside public repos, and wording matches evidence strength.
